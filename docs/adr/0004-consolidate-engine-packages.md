# Consolidate engine packages into one @svelte-pdf/engine

We consolidate react-pdf's ~10 framework-agnostic packages (primitives, fns, types, font, image, textkit, stylesheet, layout, render, pdfkit, math) into a single `@svelte-pdf/engine` package, rather than keeping the same granular structure. The natural seam in this project is between the framework-agnostic engine and the Svelte-specific renderer. Consolidating eliminates the internal dependency complexity while keeping the clean engine/Svelte boundary. Users install one package (`@svelte-pdf/renderer`) and get everything. The engine remains usable without Svelte — if someone later wants a Vue or Solid renderer, they'd build on the same engine. The trade-off is losing fine-grained versioning and the ability to depend on a single sub-package (e.g. just the layout engine).
