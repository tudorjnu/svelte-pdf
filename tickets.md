# Tickets: svelte-pdf v1

A library for creating PDF documents using Svelte 5 components, on the browser and server. Built by vendoring react-pdf's framework-agnostic engine and replacing the React layer with Svelte. Reference spec: `.scratch/svelte-pdf-v1/PRD.md`.

Work the **frontier**: any ticket whose blockers are all done. For a purely linear chain that means top to bottom. Tickets 3 and 4 can run in parallel after 2.

## 1. Vendor @svelte-pdf/engine

All internal imports changed from `@react-pdf/*` to `@svelte-pdf/engine`. The ~204 engine tests from react-pdf pass with updated import paths. The package builds successfully and exports the same APIs the renderer will consume (layout, render, pdfkit, font store, primitives, stylesheet, fns, types).

## 2. Tracer bullet — render a simple PDF from Svelte components

**What to build:** The thinnest end-to-end path proving the architecture works. A user writes a Svelte component using `<Document>`, `<Page>`, `<View>`, and `<Text value="..." />` and renders it to a PDF buffer on the server via `renderToBuffer(MyDocument, props)`. The Svelte components build the element tree via context API during initialization (`setContext`/`getContext` — `pdf-parent` for tree structure, `pdf-root` for re-render notification). The `pdf()` function takes the element tree and processes it through the engine (layout → render → pdfkit). The `renderToBuffer` wrapper uses Svelte's `render()` with a shared container to capture the tree. One visual regression test passes — a simple document (a page with a colored `View` containing `Text`) produces a PDF pixel-identical to the equivalent react-pdf output.

**Blocked by:** 1. Vendor @svelte-pdf/engine

- [x] `Document.svelte`, `Page.svelte`, `View.svelte`, `Text.svelte` created using Svelte 5 context API for tree-building
- [x] `pdf()` function works — takes element tree container, produces PDF via engine (layout → render → pdfkit)
- [x] `renderToBuffer(component, props)` server API works using Svelte's `render()` with shared container
- [x] `Text` component creates `TEXT_INSTANCE` nodes from the `value` prop
- [x] Visual regression test infrastructure adapted from react-pdf (renderComponent helper: Svelte component → renderToBuffer → pdfjs-dist → @napi-rs/canvas → PNG → snapshot comparison)
- [x] One visual regression test passes — simple document produces a stable baseline PNG (react-pdf pixel equivalence to be validated once react-pdf renderer tests can be run; current baseline is generated by the svelte-pdf pipeline)

## 3. Full core components + browser rendering

**What to build:** All 7 core components are available and working. The remaining components (`Link`, `Note`, `Image`) are added using the same context API pattern. Browser-side rendering works: `usePDF()` returns reactive state (`{ url, blob, loading, error }`) using Svelte 5 `$state` in a `.svelte.js` module; `PDFViewer.svelte` renders the PDF in an iframe via blob URL; `PDFDownloadLink.svelte` triggers a download. Reactivity works: `$effect` in each component syncs prop changes onto its node and notifies the root, which queues a batched re-render. `renderToFile` and `renderToStream` server APIs work. The `Font` registration API (`Font.register`, `Font.registerHyphenationCallback`, `Font.registerEmojiSource`) is exposed. All 20 visual regression tests from react-pdf pass against the 81 PNG baselines.

## 4. Markdown support

**What to build:** The `@svelte-pdf/markdown` package with a `<Markdown content="..." />` Svelte component. The component parses the markdown string via `marked.lexer()`, walks the token AST, and produces a subtree of `TEXT`, `TEXT_INSTANCE`, `LINK`, and styled `TEXT` nodes registered with the parent via context API. Supports: headings, paragraphs, bold, italic, strikethrough, links, unordered/ordered lists, blockquotes, inline code, horizontal rules. Markdown-specific visual regression tests pass with newly created baselines. The package depends on `@svelte-pdf/renderer` and `marked`.

**Blocked by:** 2. Tracer bullet — render a simple PDF from Svelte components

- [x] `@svelte-pdf/markdown` package created with `marked` dependency
- [x] `<Markdown content="..." />` component parses markdown and produces element tree nodes via context API
- [x] Markdown AST → element tree mapping covers: headings (styled TEXT with fontSize), bold/italic/strikethrough (styled TEXT), links (LINK nodes with href), lists, blockquotes, inline code, horizontal rules
- [x] Markdown-specific visual regression tests pass with new baselines (headings, bold, italic, links, lists, blockquotes)
- [x] Package builds and exports the `Markdown` component
